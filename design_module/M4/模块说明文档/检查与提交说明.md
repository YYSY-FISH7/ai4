# M4 验证与提交说明

基线：develop e760b15（2026-11-03）。验证使用 Ubuntu 20.04 / ROS Noetic / Python 3.8 的独立源码工作空间；复用原 VM 的隔离依赖和本地演示素材，不修改系统库。

## 本次结果

独立最新源码工作空间 catkin_make 通过；114 项单测和相机/检测/跟踪三个 ROS E2E 通过；四个 notebook 重新执行并检查输出图。真实图片阶段保留 5 条样本要求，在 6.6 秒内收齐。系统 NumPy/cv2 未改动。

## 验证入口

- `bash scripts/冲突库下载/install_m4_deps.sh --check`：隔离路径、版本、CPU NMS 和系统 cv2。
- `bash scripts/check_m4.sh`：M4 单测及相机、检测、跟踪三个实际 ROS E2E。
- 四个 M4 notebook 从空内核执行并检查输出图。detector 图为实际 COCO 模型推理，其余合成消息/轨迹明确标注。
- `bash scripts/run_m4.sh`、verify、stop：图像和 ROS 消息持续更新、停止保留其他进程。
- 小联调按项目规范放在 `test/flow/litter/M0-M4` 与 `M4-M5`；缺图像、空航迹、未观察到状态转换应失败，不能用假源或自行启动接收方代替正式联调。

检测 E2E 保留至少 5 条消息要求。CPU 忙时在至少观察 6 秒后继续收集，最长 30 秒；超时仍不足或没有目标会失败。该测试检查连通与结果有效性，不把最低样本数当成飞控 50Hz 指标。

## 提交范围

仅 M4 纯逻辑、三个节点、对应配置/launch、四个 notebook、测试、演示和依赖工具，以及 M4 文档。.gitignore 仅追加 M4 生成物排除规则；公共依赖登记仅更新 M4 段，保留其他模块记录。以 PR 合并到 develop。

旧演示 live_stream.py、live_view.py、set_camera_source.sh 由 console.py/html 和 scripts/run_m4.sh 替代。模型、视频、隔离库、构建目录、桌面快捷方式和本机历史备份不提交。
