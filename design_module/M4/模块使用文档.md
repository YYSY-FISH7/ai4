# M4 使用文档

本文是 M4 唯一操作入口。环境：Ubuntu 20.04、ROS Noetic、Python 3.8，使用源码工作空间。当前虚拟机路径 `/home/demo/桌面/ai4`。Windows 不需要安装 ROS 或模型库。

## 1. 当前虚拟机一键运行

Ubuntu 桌面双击 **M4视觉感知台**；如果显示文本文件，先关闭编辑器，在图标右键选择“允许启动”，再双击。

也可以打开 Ubuntu 终端，复制这一行：

```bash
bash /home/demo/桌面/ai4/scripts/run_m4.sh
```

启动后等待模型预热，Ubuntu 浏览器访问 <http://127.0.0.1:8092/>。Windows 浏览器访问 <http://192.168.183.128:8092/>；虚拟机 IP 改变后用 `hostname -I` 查看。Windows 的 127.0.0.1 指 Windows 本身。

成功标志：图像持续更新；检测、跟踪消息计数持续增加；页面没有进程退出或数据过期提示。终端自检：

```bash
bash /home/demo/桌面/ai4/scripts/run_m4.sh verify
```

这会检查真实 ROS 发布者和消息更新，不能代替完整无人机验收。默认使用公开 COCO 权重及公交车照片生成的运动视频：模型推理是真实运行的，视频运动是合成的；尚不能证明能够识别无人机。演示使用独立 ROS master 11321，不占用仿真默认 11311。

## 2. 停止、状态和重启

```bash
bash /home/demo/桌面/ai4/scripts/run_m4.sh status
bash /home/demo/桌面/ai4/scripts/run_m4.sh stop
bash /home/demo/桌面/ai4/scripts/run_m4.sh restart
```

停止只清理本次脚本创建的进程。也可双击桌面“停止M4视觉感知台”。重复启动同模式会打开现有页面；切换演示/仿真模式先 stop。日志位于 `/tmp/m4-console-1000/`，优先查看 session.log、detector.log、tracker.log。

## 3. 换用自己的视频或权重

先 stop，再运行（替换为真实绝对路径）：

```bash
bash scripts/run_m4.sh start --video /绝对路径/视频.mp4 --model /绝对路径/权重.pt
```

相对路径命令须在项目根目录运行；也可使用脚本的绝对路径。默认以 CPU、320 输入边长、0.1 检测门槛运行，性能以页面实际速率为准。低检测门槛用于跟踪第二阶段关联；锁定门槛由状态机决定。此脚本不会安装依赖或临时下载模型。

## 4. 接组长的实际仿真

先由队友启动仿真、图像源和状态机，确认真实相机话题与无人机权重。停止本地演示，然后：

```bash
bash scripts/run_m4.sh sim --master http://127.0.0.1:11311 --topic /实际相机话题 --model /绝对路径/无人机权重.pt
```

仿真模式不启动相机、不启动状态机，图像缺失时失败退出，不用公交车图替代。若已有 detector/visual_tracker，先请原启动者停止它们，避免重复发布。修改话题后要重启节点，运行中 `rosparam set` 不会自动重新订阅。

正式联调由双方模块实际运行后检查：

```bash
bash test/flow/litter/M0-M4/run.sh check --topic /实际相机话题 --no-gui
bash test/flow/litter/M4-M5/run.sh check
```

检查器不会启动接收方。M0→M4 默认要求目标场景确实检出目标，明确测试空场景才用 `--allow-empty`。M4→M5 需要非空航迹、稳定 ID 及实际 RADAR_GUIDE→VISUAL_LOCK 切换，已锁定后才开始观察不足以证明状态转换。

## 5. 新克隆工程首次准备

仅在依赖或素材缺失时执行；已有虚拟机不需要重复安装。

```bash
cd /你的路径/ai4
bash scripts/冲突库下载/install_m4_deps.sh --check
# 检查失败且确认是首次安装时，显式安装隔离依赖：
bash scripts/冲突库下载/install_m4_deps.sh --install
bash test/M4_现场验证/实时演示/get_assets.sh
source /opt/ros/noetic/setup.bash
cd catkin_ws
catkin_make
cd ..
bash scripts/run_m4.sh
```

依赖固定为当前 VM 已验证版本，安装到根目录 lib/m4；不安装 opencv-python，不升级系统 NumPy。Python 3.8 老环境使用组长已同意的隔离兼容方案，不能把这份锁文件当成任意 Python 版本的通用依赖。现有隔离目录不会自动覆盖；损坏时先备份再处理。离线时需要事先准备依赖和模型素材。

## 6. 自检与笔记本

```bash
bash scripts/check_m4.sh
```

包含 M4 单测和相机、检测、跟踪三个独立 E2E，使用 11331/11332/11333；端口已占用会明确失败，不复用其他人的 master。各阶段日志在对应测试目录 logs/。本脚本不包含队友仿真验收。

四个 code/ 下的 M4 ipynb 保留真实执行输出；在已 source ROS 和工作空间的终端启动 Jupyter，重启内核，从头运行。detector.ipynb 是实际 YOLO 推理，其他合成消息/轨迹图均明确标注用途。

## 7. 常见问题

- 页面打不开：先运行 status，查看 session.log；Windows 请使用 VM IP。
- 有画面但框少或没有框：检查模型类别、场景、detector.log；不能用人为画框代替检测。
- CPU 速率低：页面显示实际处理速率；跟踪按处理帧计数。推理 FPS 与飞控 50Hz 指令发送是不同指标。
- 画面面积达到 2%：仅表示面积占比达到阈值，没有标定不能换算成距目标 100 米。
- 本次运行或测试失败：保留原日志并按错误处理，不能把无消息、空输入或跳过目标阶段记为验收通过。

实现和改动范围见 [内部实现说明](模块说明文档/实现说明.md)。
