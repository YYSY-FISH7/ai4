# M0 模块使用文档

所有命令均从 **ai4 项目根目录**的 Bash 终端执行，需已完成项目依赖安装和 catkin 构建。

## 1. 启动仿真

```bash
source /opt/ros/noetic/setup.bash && catkin_make -C catkin_ws -DPYTHON_EXECUTABLE=/usr/bin/python3 -j2
bash catkin_ws/src/uav_sim/scripts/start_mounted_radar.sh
```

等待 Gazebo 与实时查看器打开，两机可见并运动；默认不录制。不要重复启动。

## 2. 查看世界位姿

在 ai4 根目录打开第二个终端：

```bash
bash catkin_ws/src/uav_sim/scripts/sensor_live.sh pose
```

入口自动加载 ROS 环境及活动实例的 `connection.bash`，核验 master 和两个话题实际发布，无需手动填写运行目录。

`/radar/uav_pose_world` 的 `pose.position.x/y/z` 是搭载雷达的观测无人机模型原点在 Gazebo `world` 中的位置（米），不是目标机位置或经纬度；`pose.orientation` 是姿态四元数，`header.stamp` 与对应点云采样时间一致。点云仍在 `radar_link`，未转换成世界坐标点云。

## 3. 同时录制点云与位姿

在 ai4 根目录另开终端：

```bash
bash catkin_ws/src/uav_sim/scripts/sensor_live.sh record
```

入口自动连接活动实例并显式录制 `/radar/points` 和 `/radar/uav_pose_world`，打印实际 bag 路径，保存到项目 `data/radar`。新增位姿不是原记录器自动保存的内容。

离线按两话题完全相同的 `header.stamp` 配对；仿真重置或采样时间回退时分段处理，避免重复时间戳跨段配对，缺失位姿不能沿用上一帧。

## 4. 停止

先在录制终端按 **Ctrl+C**，等待 bag 保存完成；再在仿真启动终端按 **Ctrl+C**，等待所属进程退出。查看位姿的终端也可用 **Ctrl+C** 退出。不要全局杀死 ROS/Gazebo。

没有活动实例时先启动并等待就绪；多个活动实例时入口会列出可直接复制的选择命令，不会按目录时间猜测。查看活动实例：

```bash
bash catkin_ws/src/uav_sim/scripts/sensor_live.sh list
```

若启动失败，查看启动终端及其打印的本次运行目录中的 `console.log`、`startup_error.txt`。

## 5. 启动测试

全部测试的通过判据以脚本自身退出码为准：`0` 为通过，非 `0` 会打印失败原因。

### 5.1 前置条件

```bash
export DISPLAY=:0                      # 必须：相机图像依赖 OGRE 渲染，无 X 时相机帧 age 一直增长
source /opt/ros/noetic/setup.bash
source catkin_ws/devel/setup.bash
source lib/venv/env.bash
```

- 所有脚本用系统 `/usr/bin/python3`（ROS Noetic 的 rospy 装在该解释器下），不要用 venv 的 3.12。
- 启动前确认没有残留 Gazebo：`pgrep -x gzserver` 应无输出，否则先结束旧进程（`start_mounted_radar.sh` 也会拒绝重复启动）。
- M0 使用独立 ROS master（端口随机），涉及 ROS 命令时需先 `source data/radar/<run_dir>/connection.bash`。

### 5.2 测试清单

| 测试 | 类型 | 依赖 | 耗时 |
|---|---|---|---|
| `test/uav_sim/radar_pose/test_active_run.py` | 离线单元测试 | 无 | < 5 s |
| `test/uav_sim/radar_pose/run_gazebo_check.py` | Gazebo 回归 | 审计插件、DISPLAY | 2~3 min |
| `test/uav_sim/radar_pose/compare_model_pose.py` | 离线核对 | 上一步的 run 目录 | < 5 s |
| `test/uav_sim/sensor_recording/run_e2e.py` | 录制端到端 | DISPLAY | 1~2 min |
| `test/uav_sim/sensor_recording/run_replay.py` | 离线回放 | 上一步的 `live_result.json` | < 1 min |
| `catkin_ws/src/uav_sim/scripts/check_sensor_run.py` | 离线验收 | `record:=true` 的 run 目录 | < 10 s |
| `test/uav_sim/radar_pose/check_live_bag.py` | bag 配对核对 | `sensor_live.sh record` 生成的 bag | < 10 s |

### 5.3 逐项启动

#### 5.3.1 入口单测（最快，先跑这个）

```bash
/usr/bin/python3 test/uav_sim/radar_pose/test_active_run.py
```

预期：`Ran 5 tests`、`OK`。

#### 5.3.2 逐帧位姿回归

先编译一次审计插件与故障注入器：

```bash
cmake -S test/uav_sim/radar_pose -B /tmp/ai4-pose-audit-build
cmake --build /tmp/ai4-pose-audit-build -j2
```

再跑四阶段回归（会自行启动/停止 Gazebo，`gui:=false`）：

```bash
RUN_DIR="data/radar/pose_validation_$(date +%Y%m%d_%H%M%S)"
/usr/bin/python3 test/uav_sim/radar_pose/run_gazebo_check.py \
    "$RUN_DIR" /tmp/ai4-pose-audit-build/libmodel_pose_audit.so
```

预期：输出 `233 pairs` 左右的配对统计、`errors 0`，并打印 run 目录。随后核对：

```bash
/usr/bin/python3 test/uav_sim/radar_pose/compare_model_pose.py "$RUN_DIR"
```

预期：四个阶段（static / observe / target / reset）均有配对，`unmatched` 为空。

#### 5.3.3 录制端到端与离线回放

```bash
/usr/bin/python3 test/uav_sim/sensor_recording/run_e2e.py
/usr/bin/python3 test/uav_sim/sensor_recording/run_replay.py
```

预期：`run_e2e.py` 打印 `reason='duration_reached'`、`returncode=0`；`run_replay.py` 打印回放自检字段全部为 `true`。

注意：`run_e2e.py` 是录制验收，必须带 `record:=true`（脚本内已补齐）。若改回默认不录制，它会一直等不到 `frames.csv` 而超时。

#### 5.3.4 离线验收（消费已有 run 目录）

```bash
# 需先有一次 record:=true 的运行
bash catkin_ws/src/uav_sim/scripts/start_mounted_radar.sh record:=true
# Ctrl+C 后记下运行目录，再执行：
/usr/bin/python3 catkin_ws/src/uav_sim/scripts/check_sensor_run.py data/radar/<run_dir>
```

预期：`camera_complete=true`、`radar_complete=true`、退出码 0。

#### 5.3.5 bag 配对核对

```bash
bash catkin_ws/src/uav_sim/scripts/start_mounted_radar.sh   # 另开终端保持运行
timeout -s INT 25 bash catkin_ws/src/uav_sim/scripts/sensor_live.sh record
/usr/bin/python3 test/uav_sim/radar_pose/check_live_bag.py data/radar/radar_pose_<时间>.bag
```

预期：`passed: true`、`paired_frames > 0`。

注意：该测试要求 bag 内同时有 `/radar/points` 与 `/radar/uav_pose_world`，只有 `sensor_live.sh record` 生成的 bag 满足；`record:=true` 产生的 `raw.bag` 不含 `uav_pose_world`，不能用于此项。

### 5.4 一键顺序执行

```bash
set -e
cd /home/demo/桌面/ai4
export DISPLAY=:0
source /opt/ros/noetic/setup.bash
source catkin_ws/devel/setup.bash
source lib/venv/env.bash

/usr/bin/python3 test/uav_sim/radar_pose/test_active_run.py

cmake -S test/uav_sim/radar_pose -B /tmp/ai4-pose-audit-build >/dev/null
cmake --build /tmp/ai4-pose-audit-build -j2 >/dev/null
RUN_DIR="data/radar/pose_validation_$(date +%Y%m%d_%H%M%S)"
/usr/bin/python3 test/uav_sim/radar_pose/run_gazebo_check.py \
    "$RUN_DIR" /tmp/ai4-pose-audit-build/libmodel_pose_audit.so
/usr/bin/python3 test/uav_sim/radar_pose/compare_model_pose.py "$RUN_DIR"

/usr/bin/python3 test/uav_sim/sensor_recording/run_e2e.py
/usr/bin/python3 test/uav_sim/sensor_recording/run_replay.py
```

## 6. 当前状态与已知限制

- 上述 7 项均可在本机通过；其中 `run_gazebo_check.py` 与 `run_e2e.py` 必须带 `DISPLAY`。
- `test/uav_sim/radar_3d/` 已删除：它面向早期的 181×5 地面平面雷达，与当前 181×25 机载配置不符。
- `test/uav_sim/camera_motion/` 为早期桌面录屏验收脚本，依赖手工放置的中文产物与固定屏幕分辨率，未维护，功能已被第 5.3.3 节覆盖。
- M0-M1 联调的可视化脚本不属于本模块测试，见 `test/flow/M0-M1/python/live_centroid_view.py`。
