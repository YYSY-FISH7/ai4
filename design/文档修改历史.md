# 文档修改历史

> 记录各版本对设计文档的修改内容与依据，便于追溯。

---

## 1.1 修改

**主题**：新增控制侧纯数据类型，消除「纯逻辑接口直接使用 ROS 消息类型」的矛盾（壳核分离原则的一致性补全）。

**背景**：`函数接口.md` / `无人机项目实施拆解文档.md` 中 navigator、pid 的纯函数签名直接使用了 ROS 消息类型 `mavros_msgs/PositionTarget`、`geometry_msgs/PoseStamped`，与「纯逻辑不依赖 ROS」原则冲突（`design/python代码移植到ros平台方法整理.md` §1.2）。

**修改内容**：

1. **`数据类型.md`**
   - 第二章新增三个纯数据类型：`Waypoint`（2.7）、`Pose`（2.8）、`PositionCommand`（2.9）。
   - 第四章原「文档引用但未定义的 `Waypoint`」改为指向 2.7，无遗留未定义类型。

2. **`函数接口.md`**
   - 纯函数签名：`PositionTarget` → `PositionCommand`，`PoseStamped` → `Pose`（模块 3、6）。
   - `send_waypoint` 返回类型由 `None` 改为 `PositionCommand`，作用改为「航点 → 位置类指令转换（纯转换，不发布）」。
   - 设计原则第 6 条、模块 6 职责同步 `PositionCommand` 表述。
   - 模块 7 补充指令类型说明：mux 透传 `mavros_msgs/PositionTarget`，不涉及 `PositionCommand`。

3. **`无人机项目实施拆解文档.md`**
   - 同步模块 3.3 / 3.6 的函数签名与注释（`send_waypoint` / `hover_setpoint` / `on_timer` / `stop_setpoint`）。
   - 第二章 `pid_controller` 节点职责、第四章「setpoint 映射」、第八章第 8 条同步 `PositionCommand` 表述。

4. **`函数调用关系图-flowchart.md`**
   - 模块 3（导航）内部调用图：边标签 `PositionTarget` → `PositionCommand`，`send_waypoint` 节点标签改为「航点→位置指令」。
   - 总图注释同步，并补充「发布前由节点壳转换为 `mavros_msgs/PositionTarget`」。

5. **消息镜像 dataclass 补齐（`Detection` → `DetectedTarget` 统一）**
   - `数据类型.md`：删除 2.4 `Detection`（与 `DetectedTarget` 字段重复）；新增 2.4「消息镜像 dataclass」小节，定义纯 `Track`（发布版）、`VisualTrack`、`DetectedTarget` 三个同名纯类型。
   - `函数接口.md`：`detect` / `track` 的 `list[Detection]` → `list[DetectedTarget]`；`waypoints_from_track`（3.1）与 `evaluate_radar_lost`（8.2）的输入说明由「消息 `Track.msg`」改为「纯类型 `Track`」。
   - `无人机项目实施拆解文档.md`：3.4 删除 `Detection` dataclass，`detect` 返回 `list[DetectedTarget]`；3.5 `track` 入参 `list[Detection]` → `list[DetectedTarget]`；3.3 注释「消息 Track.msg」改为「纯类型 Track」。
   - `TrackState` → `Track.msg` 的转换说明改为三层：`TrackState` → 纯 `Track`（dataclass）→ `Track.msg`（主文档 3.2、函数接口 模块 2）。

**不变的约定**：
- 话题 `/ctrl/radar`、`/ctrl/visual`、`/mavros/setpoint_raw/local` 的消息类型仍为 ROS 标准 `mavros_msgs/PositionTarget`；位姿话题仍为 `geometry_msgs/PoseStamped`。
- 纯类型（`PositionCommand` / `Pose` / `Waypoint`）仅存在于纯逻辑内部，节点壳负责装包 / 拆包。
- 消息镜像纯类型（`Track` / `VisualTrack` / `DetectedTarget`）与 `.msg` 同名、字段一致；纯逻辑用纯 dataclass，节点壳负责 `.msg` ↔ 纯 dataclass 拆包 / 装包。
- `control_mux` 为纯转发节点，透传 ROS 消息、不生成不解释指令内容。
