# 整体联调任务定义（T1–T5）

> 以任务为导向的整体联调：每个任务 = 一个完整飞行场景 + 量化通过判据，独立判定「过 / 不过」。
> 依据《拆解文档》第七章验收标准与第八章技术决策整理；判据数值取自第七章「量化性能基线」（允许整定，改动须记录）。

## 联调前置（各任务共用）

- 一键 launch：Gazebo world + 靶机脚本 + 全节点栈一次拉起，场景可重复；
- 可视化：RViz 看航迹 / 航点，rqt 看误差与 setpoint 曲线；
- 测试钩子：支持 `rostopic pub /state` 强制状态 / 通道（T2、T4 不必等自然触发）；

---

## T1 雷达链起飞引导闭环

- **对应验收**：阶段 2 + 3
- **场景**：靶机 8 字飞行；拦截机起飞切 OFFBOARD，雷达链引导逼近
- **链路**：`radar_sim → /cluster → /tracker → /navigator → /control_mux → PX4`（状态机保持 `RADAR_GUIDE`）

**判据**：

1. 稳定保持 OFFBOARD，setpoint 50Hz 无断流；
2. 航迹位置误差 < 1 m（对 `/target/pose` 真值）；
3. 断续点迹连成平滑航迹（协方差收敛可见）；
4. 连续 K 帧无航迹时 navigator 自判悬停（`hover_setpoint`），不掉出 OFFBOARD。

**重点观察**：`z_thresh`、`eps / min_samples` 是否需随噪声整定；卡尔曼 predict/associate/update 时序；最近邻关联的交叉错配留记录。

## T2 视觉链伺服验证

- **对应验收**：阶段 4 前置
- **场景**：靶机视觉模型进入画面；测试钩子强制 mux 放行 `/ctrl/visual`
- **链路**：`camera_node → /detector → /visual_tracker → /pid_controller → /control_mux`

**判据**：

1. 三通道符号正确：偏右→右偏航；偏下→俯冲；面积小（远）→前进推力大；
2. 锁定像素抖动 < 20 px；
3. PID 阶跃超调 < 15%；
4. 深度逼近段 `1/面积` 冷启动

**重点观察**：`FRAME_BODY_OFFSET_NED` 下 yaw_rate / body velocity 映射符号；空 `Detections` / `VisualTrackArray` 按「空也发」发布。

## T3 兜底与故障行为联调（安全关键）

- **对应验收**：阶段 3 failsafe 行为 + 第八章第 7/8/9 条
- **场景**：T1 基础上逐点注入故障，注入一类、记录一类、恢复一类

**注入清单**：

| 注入项 | 预期行为 |
|---|---|
| kill `/cluster`（雷达链断流） | navigator 短时保持→超时 `hover_setpoint` 悬停，不掉 |
| kill `/detector`（视觉链断流） | pid 短时有界保持→超时 `stop_setpoint` 零速，不掉 |
| 上游发空数组 | 空数组不刷新 `valid_age`；持续空收敛到默认指令，不得无限保持旧速度指令 |
| 目标飞出画面 | 状态机 M 帧回退逻辑属 T4；本任务只看 pid 侧有界保持 |
| 杀掉 mux 上游双方（流断 > 0.5s） | PX4 OFFBOARD failsafe 切出（保命兜底） |

**判据**：

1. 短时无数据→重发上一条；长时无数据→navigator 悬停 / pid 零速，全程不掉（failsafe 项除外）；
2. 数据恢复后自动恢复跟踪，无需人工重发；
3. 无陈旧速度指令被无限重发（方案 B：上游死则流断、failsafe 兜底）；
4. 保持窗口与 `hold_timeout` 设定一致，时钟层行为可复现。

## T4 状态机切换 + 仲裁联调

- **对应验收**：阶段 4 切换触发 + 第四章规则 + 切换延迟 < 100 ms
- **场景**：脚本化靶机由远及近，bbox 面积自然越过 2% 阈值；辅以测试钩子构造退出 / 熔断路径

**判据**：

1. 切换延迟 < 100 ms（条件满足到 mux 放行视觉通道）；
2. N/M/K 计数符合转移表：视觉锁定连续 N 帧进 `VISUAL_LOCK`；连续 M 帧丢失回 `RADAR_GUIDE`；`RADAR_GUIDE` 下连续 K 帧无雷达航迹进 `SEARCH/RTH`；雷达恢复退出；
3. 优先级：`RADAR_GUIDE` 下视觉锁定与雷达丢失并存时进 `VISUAL_LOCK`；`SEARCH/RTH` 仅由雷达恢复退出；
4. 帧计数以 `/detections` 到达为唯一节拍（三路回调只刷缓存、仅 `/detections` 推进），某路慢不误判为空；
5. `/state` 按变化发布，mux 通道跟随；`SEARCH/RTH` 及其他值回退 `/ctrl/radar`；
6. 记录 `RADAR_GUIDE → VISUAL_LOCK` 切换瞬间指令突变幅度，为第九章优化 2「硬切是否达标」提供数据。

## T5 全流程拦截 mission（中期验收）

- **对应验收**：阶段 5「雷达→视觉无卡顿」+ 方案书评估维度 1/2
- **场景**：靶机动态飞行、全节点运行，mission 一次跑通

**剖面**：起飞→OFFBOARD→雷达引导（`RADAR_GUIDE`）→面积过阈值连续 N 帧→`VISUAL_LOCK`→末端逼近（达撞击阈值转恒速/减速）→撞击或贴身跟随→视觉丢失 M 帧→回 `RADAR_GUIDE` 重搜→降落

**判据**：

1. 全程无卡死、无通道错配（mux 任一时刻只放行一路，切换日志可定位）；
2. 雷达→视觉切换平滑无卡顿（结合 T4 突变幅度判定）；
3. 末端面积判据正确：达阈值转恒速 / 减速，不持续加速；
4. 视觉丢失按 M 帧回退重搜，重搜中兜底行为符合 T3 判据；
5. 全程录包，可复盘每次状态切换时点与指令内容。

---

## 依赖顺序

```
T1 ──→ T2 ──→ T3 ──→ T4 ──→ T5
```

- T1 不过不进 T2（雷达链是引导航段的兜底通道）；
- T3 安排在 T4 之前——兜底行为是切换联调的安全前提；
- T5 需 T1–T4 全部通过；子任务失败先在对应任务内定位，不带病进入 T5。
