## M0（雷达数据源）

### M0-02 · 默认入口 gui:=true 启动超时，GUI 视角就绪凭证未生成【待解决】

- 提出：张 · 2026-11-08
- 类型：缺陷

**现象**
- 执行 `bash catkin_ws/src/uav_sim/scripts/start_mounted_radar.sh`（默认 `gui:=true`），约 150 秒后
  `start_sensor_clock` 以 exit code 1 退出，roslaunch 随即 `Initiating shutdown!`，所有节点（含
  `gazebo_gui`）被清理，现场表现为「GUI 窗口突然消失」。
- 同一时刻数据链本身正常：`startup_health.json` 中 `ages_wall_s` 的 clock/camera/radar 均在 0.3 s 内，
  `viewer_frames` 持续增长（camera 567 / radar 403）。
- 唯一未就绪项是 `gui_view_ready: false`。

**定位**
- `catkin_ws/src/uav_sim/scripts/start_sensor_clock.py` 第 96–98 行：`gui_required` 为 true 时，
  `gui_view_ready = (run_dir/'spectator_view.txt').exists()`，文件不存在即永不就绪；该节点为
  `required="true"`，退出后连带清理整个 launch。
- `spectator_view.txt` 由 Gazebo GUI 插件 `ai4_scene_view`（`catkin_ws/src/uav_sim/src/scene_view.cpp`）
  在 `scene->GetVisual("static_uav")` 与 `scene->GetVisual("target_uav")` 同时非空后写入。
- 本次该文件始终未生成，说明插件 `Apply()` 未进入写文件分支，或 GUI 连接的场景中取不到这两个模型的
  视觉对象。

**影响**
- 默认入口无法启动到 `running`，150 秒后整体退出。
- 不影响点云与聚类链路：以 `gui:=false` 启动可正常 `running`，`sensor_viewer` 的相机与雷达窗口照常
  弹出，`/radar/points`、`/radar/uav_pose_world` 正常发布并可被 M1 消费。

**证据**
- 运行目录：`data/radar/20261108_061243_0f6fdf66-43de-4250-9907-5916ee4a8f5d`
- `console.log`：`REQUIRED process [start_sensor_clock-12] has died!`（exit code 1），随后
  `Initiating shutdown!`、`[gazebo_gui-3] killing on exit`（属 roslaunch 清理，不是崩溃）。
- `startup_error.txt`：`startup data/motion timeout: {..., 'gui_view_ready': False, ...}`
- 历史对照：2026-11-06 同一入口曾正常到达 `running`；本轮（重新编译后）稳定失败，差异原因待查。

**补充**
- 该现象易被误认为「启动 M1 后 GUI 被杀死」，实际是超时后的清理动作。若 GUI 在 M1 启动后数秒内
  即消失，应另行排查 M1 侧 `roslaunch` 是否因未 source 运行目录的 `connection.bash` 而另起 roscore。

## M3（navigator）

### M3-01 · ENU/NED 坐标系不一致【待解决】

- 提出：张 · 2026-10-28
- 类型：缺陷（待确认）

**现象**
- `code/navigator.py` 输出指令固定用 `LOCAL_NED_FRAME = 1`（即 `PositionTarget.FRAME_LOCAL_NED`），但填入 `position` 的两处数据源都是 ENU（z 向上）：
  1. `waypoints_from_track` 直接拿 `track.position`（世界/雷达 ENU）当航点；
  2. `hover_setpoint` 用 `/mavros/local_position/pose`（MAVROS 输出为 ENU）填当前位置。

**问题**
- `FRAME_LOCAL_NED` 是 NED（z 向下、y 向右），与 ENU 轴不同。`M3/模块使用文档.md`「坐标与使用边界」写“由 MAVROS 负责 ENU/NED 转换”，但 `setpoint_raw/local` 的 `FRAME_LOCAL_NED` 是直接把 x/y/z 按 NED 交给飞控，不自动做 ENU→NED，该说法需核实；若属实，则高度（z）和横向（y）会出错。

**影响**
- 地基雷达 + 原点重合时因坐标近似重合未被暴露；换机载雷达后 `track` 变成世界 ENU，问题必然显现。

**建议**
- 在 navigator 输出前统一做一次 ENU→NED（含 hover 分支），或明确“由谁负责转换”，不要依赖“MAVROS 自动转换”的假设。
